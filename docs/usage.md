# 활용법

세 가지 방식이 있습니다. 목적에 따라 고르세요.

| 방식 | 설치 | 쓸 수 있는 것 | 언제 |
|---|---|---|---|
| **브라우저 앱** | 없음 | 조항 요약 · 비교표 · 출처 | 찾아보기, 공유, 발표 |
| **`./run find`** | Python | 위 + **원문 축자 2,184청크** | 조문 인용, 근거 확인 |
| **`./run ask`** | Python + API 키 | 위 + 인용형 답변 생성 | 초안 작성 |

---

## 1. 브라우저 앱 — 가장 간편

`web/aircraft-impact.html` 파일 하나입니다. 더블클릭하면 열립니다.
서버도, 인터넷도, 설치도 필요 없습니다.

```bash
./run app          # 파일을 만들고 기본 브라우저로 엽니다
```

- **검색** — 한국어·영어 아무거나. `/` 키로 검색창 포커스, `Esc`로 지우기
- **프리셋** — 무엇을 물어야 할지 모를 때. 이 DB가 실제로 답할 수 있는 질문 8개
- **필터** — 관할(미국·체코·EU·IAEA) / 종류(조항·비교항목) / 주제 15축
- **비교표** — 12개 항목 × 15개 문서. 칸을 누르면 그 문서의 입장과 근거가 열립니다
- **문서** — 15개 소스의 서지정보와 원문 링크

**주의:** 앱에는 **큐레이션 계층만** 들어 있습니다(조항 요약·비교·출처).
NEI 07-13, IAEA 발간물, WENRA, EUR의 **축자 원문은 저작권·라이선스 대상이라
포함하지 않았습니다.** 그래서 이 파일은 공유해도 안전하고, 원문이 필요하면
아래 CLI를 쓰면 됩니다.

## 2. CLI — 원문까지 검색

```bash
./run setup                    # 처음 한 번
./run find "관통"
```

### 실제로 자주 쓰게 되는 형태

```bash
# 원문 축자만 보기 (요약 제외)
./run find "reduced Degen" --kind raw

# 관할 한정
./run find "letadla" --jurisdiction CZ --kind raw

# 주제 축으로 좁히기 (T08 = 국부손상)
./run find "scabbing" --topic T08

# 원문 대조가 끝난 레코드만
./run find "허용기준" --verification primary_source

# 청크 전문 보기 (요약 잘림 없이)
./run find "일몰" -k 1 --context
```

검색 결과 앞의 기호가 신뢰도입니다:

| 기호 | 뜻 | 인용 |
|---|---|---|
| `★` | 원문 축자 또는 원문 대조 완료 | 가능 |
| `✓` | 검색으로 확인한 요약 | 출처 링크 확인 후 |
| `~` | 미검증 요약 | 인용 전 원문 확인 |
| `!` | 조문번호·내용 불확실 | 인용 금지 |

현재 `~`와 `!`는 0건입니다(`./run gaps`로 확인).

### 원문을 더 넣기

`corpus/raw/<SOURCE_ID>/` 에 PDF나 TXT를 넣고:

```bash
./run rebuild
```

`SOURCE_ID`는 `config/sources.yaml`에 있는 값입니다(예: `IAEA-SRS-88`).
텍스트 레이어가 없는 스캔본은 읽지 못하니 텍스트가 선택되는 PDF를 쓰세요.

## 3. Claude 인용답변

```bash
export ANTHROPIC_API_KEY=...      # 또는: ant auth login
./run ask "미국과 체코의 항공기 충돌 설계기준 차이를 정리해줘"
```

검색으로 관련 조항을 모아 프롬프트에 넣고, 모델에게 **공급된 문서 안에서만**
답하고 `(레코드ID)`로 인용하도록 강제합니다. 신뢰도 등급도 답변에 반영하게 되어
있어, 미검증 요약에 기댄 문장은 그렇다고 말합니다.

근거를 눈으로 보려면 `--show-context`를 붙이세요.

## 실제 업무 시나리오

### 규제 비교표를 문서에 넣어야 할 때

`docs/comparison-matrix.md` — 12항목 × 15문서 매트릭스에 항목별 상세가 붙어
있습니다. `corpus/crosswalk/crosswalk.yaml`을 고치고 `./run rebuild`하면
매트릭스·앱이 함께 갱신됩니다.

### 특정 조문을 인용해야 할 때

```bash
./run find "50.150(d)" -k 1 --context
```

조항 레코드에는 `locator`(조문번호), `source_url`(출처), `quoted_source_text_cs`
(체코어 원문 인용)가 붙어 있습니다. 그대로 각주에 쓸 수 있습니다.

### 우리 설계가 어느 체계에 걸리는지 확인할 때

비교표 **CW-02**(적용범위)와 **CW-04**(설계기준 대 초과)부터 보세요.
그 다음 **CW-03**(위협 정의)이 중요합니다 — 세 체계가 서로 **다른 사건**을
다루기 때문에, 어떤 비교든 이 전제를 먼저 밝혀야 합니다.

### 다른 도구에 붙일 때

```bash
./run export                       # export/chunks.jsonl
```

`{id, text, metadata}` 한 줄씩 — LangChain, LlamaIndex, Chroma, pgvector 로더가
그대로 받습니다. `chunks.embedding` 컬럼이 비어 있으니 임베딩을 채워
하이브리드 검색으로 확장할 수도 있습니다.

## 알아두면 좋은 것

- **검색은 BM25(FTS5)입니다.** 의미 검색이 아니라 단어 일치입니다. 결과가 없으면
  단어를 줄이세요. 한글 조사가 붙어 안 걸리는 경우를 위한 부분일치 폴백이 있습니다.
- **비교항목 자동 확장** — 조항을 검색하면 그 조항을 인용하는 비교항목이 자동으로
  따라옵니다. "미국과 체코 차이"류 질문의 답은 비교항목에 있기 때문입니다.
  끄려면 `--no-expand`.
- **무결성 검사** — 크로스워크가 없는 조항을 가리키거나, 입장이 있는데 매트릭스
  열이 없으면 빌드가 실패합니다. 인용이 조용히 누락되는 것을 막기 위함입니다.
- **한계는 `docs/methodology.md`에 있습니다.** 특히 위협 파라미터의 3자 수치
  비교는 원리적으로 불가능합니다(미국은 SGI 통제, EUR은 라이선스).
